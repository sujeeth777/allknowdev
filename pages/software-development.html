01 / YOUR ROADMAP

Build the foundations
by doing the work.

Check off a stage when you can use and explain it. There is no deadline or certification required.

0 of 40 of 4 stages complete
STAGE 01 · GET COMFORTABLE

Programming fundamentals

Choose one language. Practice values, control flow, functions, data structures, errors and reading documentation.

  • Write small programs that transform input into useful output.
  • Use the terminal and learn to read error messages.
  • Learn how to break a problem into smaller steps.
Try: a command-line quiz, unit converter or text analyser.
STAGE 02 · UNDERSTAND THE WEB

HTML, CSS, JavaScript & HTTP

Learn semantic markup, responsive layouts, browser JavaScript, forms, accessibility and how requests connect a browser to a server.

  • Use browser developer tools to inspect and debug a page.
  • Fetch public data and show loading, empty and error states.
  • Build a page that works with keyboard and touch.
Try: a searchable directory or personal project page.
STAGE 03 · WORK LIKE A TEAM

Git, testing & maintainability

Track changes with Git, write clear commits, test important behaviour and make your code easier for another person to understand.

  • Create branches and review a diff before sharing changes.
  • Test expected behaviour and at least one edge case.
  • Document setup, decisions and known limitations.
Try: add tests and a contribution guide to an earlier project.
STAGE 04 · SHIP & ITERATE

Backend, data & deployment

Choose a small backend or static project. Learn APIs, basic data modelling, environment configuration and how to deploy safely.

  • Keep credentials out of source code and public repositories.
  • Validate input and show helpful errors.
  • Ask someone to use the app, then improve it from feedback.
Try: deploy a small app with a clear README and a working demo.

PROJECT CHALLENGE

Make a tiny community resource finder

Build a static page where people can search a handful of useful local or learning resources.

  • Use semantic HTML and a layout that works on mobile.
  • Add search and a category filter with clear empty results.
  • Include source links and a note on how you checked them.
  • Write setup instructions and invite one person to review it.
BEFORE YOU ADD A TOOL

Ask what problem it solves

Frameworks and services can help, but fundamentals make it easier to choose and debug them.

  • Can a simpler tool solve the same need?
  • Will this add ongoing cost or lock-in?
  • Can you explain how it works and what happens when it fails?
  • Does the project actually need it yet?
