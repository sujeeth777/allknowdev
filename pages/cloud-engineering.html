Make services
work in the real world.

Check off a stage when you can use and explain it. Practice locally and use isolated, low-risk environments.

0 of 40 of 4 stages complete
STAGE 01 · SYSTEMS BASICS

Linux, shell & networking

Learn files, processes, permissions, logs and common network concepts such as DNS, ports, routing and HTTP.

  • Navigate a terminal and inspect a running process.
  • Trace how a browser resolves and requests a website.
  • Understand what a firewall allows and blocks.
Try: run a local web server and document the request path.
STAGE 02 · PACKAGE & CONFIGURE

Containers & application config

Package an app, manage its configuration and understand the boundary between an image and a running container.

  • Build and run a minimal container locally.
  • Use environment configuration without committing secrets.
  • Inspect logs, resource use and graceful shutdown.
Try: containerise a small app and write repeatable run instructions.
STAGE 03 · DEPLOY & AUTOMATE

Cloud concepts & infrastructure

Explore compute, storage, identity, network boundaries and infrastructure as code. Compare options using documented requirements.

  • Deploy a tiny service in a test environment.
  • Set a budget alert and understand how to tear resources down.
  • Review access permissions and keep credentials private.
Try: describe and recreate a small environment from configuration.
STAGE 04 · OPERATE & IMPROVE

Reliability, security & cost

Observe a service, respond to failure and document operational trade-offs before trying to scale it.

  • Check health, logs and a basic service metric.
  • Test a backup or recovery procedure.
  • Review cost drivers, access and data retention.
Try: write a short runbook for one failure and its recovery.

PROJECT CHALLENGE

Deploy a small service with a runbook

Pick a tiny app you own and make its setup, operation and teardown understandable.

  • Run it locally and containerise it.
  • Deploy to a test environment with a spending limit.
  • Add health checks and a useful log message.
  • Document deployment, rollback, recovery and cleanup steps.
COST & SAFETY CHECK

Keep experiments bounded

Cloud resources can keep billing after you stop looking at them. Verify current provider terms before you start.

  • Set budget notifications before creating resources.
  • Use least-privilege accounts and private credentials.
  • Delete test resources and verify that they are gone.
  • Never test against systems you do not own or have permission to use.
